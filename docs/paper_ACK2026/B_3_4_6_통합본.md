## 3. 근거 강제의 4단계 정식화

근거 강제는 "어느 계층에서 무슨 명제를 검사하는가"에 따라 억제력이 달라진다. 표 1 은 이를 네 단계로 정리하고, 단계마다 무엇을 막고 무엇이 여전히 새는지를 적는다. 출발점은 두 간극이다. **간극 A** — 근거 좌표가 채워져 있다는 것과 그 좌표의 원문이 값을 뒷받침한다는 것은 다른 명제다. 생성 모델이 값과 좌표를 함께 지어내면 존재 수준의 제약은 그대로 통과한다. **간극 B** — 모든 근거 제약에는 면제 조항(사람 입력·구조화 입력·미검출)이 있고, 그 분기 조건을 쓰기 경로가 스스로 정할 수 있다면 제약은 값을 거르는 대신 라벨을 바꾸는 것으로 만족된다.

**<표 1> 근거 강제 사다리**

| 단계 | 강제하는 명제 (위치) | 남는 구멍 |
|---|---|---|
| E0 | 없음 — 지시만 (프롬프트) | 위반 탐지 수단 없음 |
| E1 | 근거 좌표가 존재한다 (CHECK) | 값·좌표 동시 날조(간극 A), 면제 조항 선택(간극 B) |
| E2 | 스팬 텍스트가 값을 문자열 수준에서 뒷받침한다 (TRIGGER + 토큰 계층) | 표기 변형(12 AUG 2026 / 2026-08-12)이 전부 격리 |
| E3 | E2 + 선언된 파생 규칙으로 유도 (+ 규칙표·용어사전) | 규칙이 느슨하면 다시 샘; 필드–영역 정합 미보장 |

검증을 애플리케이션이 아니라 저장 계층에 두는 이유는 비대칭에 있다. 애플리케이션 검증은 API·일괄 재처리·수동 보정 등 쓰기 경로마다 다시 구현되고 복제본은 서로 어긋나지만, 저장 계층 제약은 한 번 선언되어 모든 경로에 걸리고 우회하려면 스키마 변경이 기록에 남는다. E1 과 E2 의 경계는 명제의 경계이자 제약 기구의 경계이기도 하다. 같은 행 밖을 볼 수 없는 CHECK 로는 E1 까지만 표현되고, E2 부터는 토큰 계층을 조회하는 트리거가 필요하다(4절). 5절의 조건 P·E1·E2·E3 는 표 1 의 E0~E3 를 같은 DB 에서 설정값 하나로 전환한 것이다.

## 4. 제안 시스템

제안 시스템은 3절의 E2·E3 를 DB 의 쓰기 경계에서 구현한 프로토타입이다(그림 1).

**(그림 1)** 저장 계층 근거 검증의 흐름. 파서는 값과 함께 출처 계층(REGION·ANCHOR·LLM)과 근거 토큰 스팬을 넘기고, DB 트리거가 ① 존재 ② 내용 일치 ③ 선언된 파생을 검사해 자동 확정·격리를 가른다. *(v3.2 그림 1 재사용, 검사 항목 교체)*

### 4.1 토큰 계층과 값–근거 결속

통상의 파이프라인에서 OCR 단어 토큰은 필드값에 좌표만 남기고 폐기되므로, 저장 계층은 그 좌표 안에 무엇이 쓰여 있었는지 물을 수 없다. 제안 시스템은 OCR 토큰을 `document_token(document_id, page, idx, text, norm_text, bbox)` 에 영속화한다. `norm_text` 는 정규화(대소문자·공백·구두점 제거) 결과의 적재 시점 스냅샷으로, 규칙이 개정되어도 과거 판정의 근거가 남는다. 이 표는 OCR 출력으로만 채우고 데이터셋 라벨은 넣지 않는다(5절).

`field_value` 에는 근거 스팬 `[from, to)` 와 판정 컬럼 `derivation`(EXACT · SUBSTRING · FORMAT · GLOSSARY · SIMILARITY · NONE), `evidence_status`(GROUNDED · DERIVED · UNGROUNDED)를 둔다. 값은 선언된 파생 규칙 중 하나로만 통과하고 어느 규칙이었는지가 행에 남는다. FORMAT 의 표기 규칙표와 GLOSSARY 의 표준 용어사전(UN/LOCODE, UN/ECE Rec. 20, ISO 6346)은 트리거가 조회하도록 DB 에 적재하고 결과를 보기 전에 고정한다.

### 4.2 검증 트리거

CHECK 제약은 같은 행 밖을 조회할 수 없다. 내용 검증은 `document_token` 조회가 필수이므로 `BEFORE INSERT OR UPDATE` 트리거로 쓴다(Algorithm 1). 모드 `m` 은 단일 행 설정 표에서 읽으며, 5절의 절제 실험은 같은 입력에서 이 값만 바꾼다.

```
Algorithm 1. fn_field_value_enforce_evidence (BEFORE INSERT OR UPDATE ON field_value)
 1: m ← current mode; status, derivation ← NULL          ▷ 쓰기 경로가 준 판정은 버린다
 2: if m = P then return                                  ▷ E0: 강제 없음
 3: if extractor ∈ {MANUAL, JSON} ∨ grade = NOT_FOUND then return   ▷ 면제 (§4.3)
 4: if m = E1 then return coords present ? GROUNDED : quarantine(NO_COORDS)
 5: if span = ∅ ∧ bbox ≠ ∅ then span ← tokens whose centre ∈ bbox
 6: if span = ∅ then span ← reattach(value, θ); if none then quarantine(NO_EVIDENCE_SPAN)   ▷ §4.4
 7: T ← document_token[span]; if |T| ≠ |span| then quarantine(SPAN_NOT_FOUND)
 8: v ← norm(value); s ← norm(T)
 9: if v = s then (EXACT, GROUNDED)
10: else if type ∉ {number, date} ∧ v ⊂ s then (SUBSTRING, GROUNDED)
11: else if m = E3 ∧ (format(v,T) ∨ glossary(v,s) ∨ sim(v,s) ≥ θ) then (FORMAT | GLOSSARY | SIMILARITY, DERIVED)
12: else quarantine(CONTENT_MISMATCH)                    ▷ grade ← REVIEW_REQUIRED, 대표값 자격 유지
```

1행에서 판정 컬럼은 호출자가 넣어도 덮어쓰므로 GROUNDED 를 주장해도 지나갈 수 없다(간극 B). 7행에서 스팬이 가리키는 토큰이 없으면 좌표가 있어도 통과하지 못한다(간극 A). 10행에서 수치·날짜는 "12" ⊂ "1234" 같은 부분 일치를 인정하지 않는다.

### 4.3 격리와 면제 조항 봉인

검증 실패 시 예외로 거부하면 값이 버려져 사람이 확인할 기회도 사라진다. `quarantine` 은 행을 UNGROUNDED 로 표시하고 등급을 REVIEW_REQUIRED 로 강등하되, 검토 큐에서 사라지지 않도록 대표값 자격은 유지한다. 대신 룰 엔진·리포트·재학습 등 기계 경로는 UNGROUNDED 를 제외한 뷰 `field_value_trusted` 를 읽고, 사람은 검토 큐에서 격리값을 본다.

면제 조항(사람 입력·구조화 입력)은 없앨 수 없으나, 그 조건을 자동 경로가 스스로 골라서는 안 된다. "사람이 편집했다"는 주장은 실제 행위자 식별자를 동반하도록 CHECK(`extractor <> 'MANUAL' OR edited_by IS NOT NULL`)로 요구한다. 좌표가 없다는 이유만으로 자동 추출값을 수동 입력으로 기록하는 경로가 막힌다.

### 4.4 근거 역추적

LLM 이 채운 값에는 좌표가 없다. 6행은 이를 바로 격리하는 대신 값과 단어 유사도가 높은 토큰을 시작점으로 1~(단어 수+1) 토큰 창을 만들고, trigram 유사도가 θ 이상인 최적 창을 스팬으로 결속한다. 되찾은 스팬도 7행 이하의 같은 검사를 거치므로 역추적은 통과 조건의 완화가 아니라 검사 대상의 확보다. θ 는 결과를 보기 전에 검수 표본으로 정해 고정한다(5절). 프로토타입은 PostgreSQL(pg_trgm)·PL/pgSQL 로 구현했으며 운영 배포 상태는 아니다.

## 6. 결론 및 한계

본 논문은 근거 강제를 E0~E3 로 정식화하고, 내용 수준 강제(E2·E3)를 DB 트리거와 OCR 토큰 계층으로 구현해 선하증권 데이터에서 절제 실험으로 측정하였다. [5절: E1 의 FCR 이 0 이 아니었고(간극 A 의 실증), E2 는 UPR 을 낮추되 FQR 이 급등했으며, E3 의 파생 인정이 UPR 을 유지한 채 FQR 을 되돌렸다 — 신뢰구간 하한 기준으로 성립하는 항목만 남긴다.] 제안 구조가 보장하는 것은, **제안 트리거를 거친 자동 추출값 중** 그 값이 **OCR 토큰 계층에** 선언된 규칙으로 유도되지 않는 값은 자동 확정되지 않는다는 것이며, 모든 환각의 탐지가 아니다.

한계는 다음과 같다. (1) E3 는 값이 문서 어딘가에 실재함만 보장한다. 그 스팬이 그 필드의 자리라는 보장은 없어 다른 칸의 동일 문자열로도 통과하며, 필드–영역 정합 검증이 후속 과제다. (2) 오라클이 OCR 품질에 의존한다. OCR 이 놓친 글자는 근거 없음으로 격리되어 FQR 의 하한을 만든다. (3) 격리값은 대표값 자리를 유지하며, 검증 통과 후보의 자동 승격은 구현하지 않았다. (4) 단일 서류 유형·데이터 출처·LLM 백엔드의 단일 노드 프로토타입 평가로, 동시 쓰기 부하는 미검증이다.
