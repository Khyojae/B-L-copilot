## 3. 근거 강제의 4단계 정식화

근거 강제는 어느 계층에서 무슨 명제를 검사하는가에 따라 억제력이 달라진다(표 1). 두 간극이 단계를 가른다. **간극 A** — 좌표가 채워져 있다는 것과 그 원문이 값을 뒷받침한다는 것은 다른 명제이며, 값과 좌표를 함께 지어내면 존재 수준 제약은 통과한다. **간극 B** — 면제 조항(사람·구조화 입력)의 분기 조건을 쓰기 경로가 스스로 정하면 제약은 라벨을 바꾸는 것으로 만족된다.

**<표 1> 근거 강제 사다리**

| 단계 | 강제하는 명제 (위치) | 남는 구멍 |
|---|---|---|
| E0 | 없음 — 지시만 (프롬프트) | 위반 탐지 수단 없음 |
| E1 | 근거 좌표가 존재한다 (CHECK) | 값·좌표 동시 날조(간극 A), 면제 조항 선택(간극 B) |
| E2 | 스팬 텍스트가 값을 문자열 수준에서 뒷받침한다 (TRIGGER + 토큰 계층) | 표기 변형(12 AUG 2026 / 2026-08-12)이 전부 격리 |
| E3 | E2 + 선언된 파생 규칙으로 유도 (+ 규칙표·용어사전) | 규칙이 느슨하면 다시 샘; 필드–영역 정합 미보장 |

저장 계층 제약은 쓰기 경로마다 복제되는 애플리케이션 검증과 달리 한 번 선언되어 모든 경로에 걸리고, 우회가 스키마 변경으로 기록된다. 같은 행 밖을 볼 수 없는 CHECK 는 E1 까지만 표현하고 E2 부터는 트리거가 필요하다(4절). 5절의 조건 P·E1·E2·E3 는 E0~E3 를 설정값 하나로 전환한 것이다.

## 4. 제안 시스템

제안 시스템은 E2·E3 를 DB 의 쓰기 경계에서 구현한 프로토타입이다. 파서는 값과 함께 출처 계층(REGION·ANCHOR·LLM)과 근거 토큰 스팬을 넘기고, 저장 시점의 트리거가 존재·내용 일치·선언된 파생을 검사해 자동 확정과 격리를 가른다.

### 4.1 토큰 계층과 값–근거 결속

OCR 토큰은 통상 좌표만 남기고 폐기되므로 저장 계층은 좌표 안의 글자를 물을 수 없다. 제안 시스템은 토큰을 `document_token(document_id, page, idx, text, norm_text, bbox)` 에 영속화하고(OCR 출력만, 라벨 제외), `field_value` 에 근거 스팬 `[from, to)` 와 `derivation`(EXACT · SUBSTRING · FORMAT · GLOSSARY · SIMILARITY · NONE), `evidence_status`(GROUNDED · DERIVED · UNGROUNDED)를 둔다. 값은 선언된 파생 규칙 중 하나로만 통과하고 어느 규칙이었는지가 남는다. FORMAT 규칙표와 GLOSSARY 용어사전(UN/LOCODE, UN/ECE Rec. 20, ISO 6346)은 DB 에 적재해 결과를 보기 전에 고정한다.

### 4.2 검증 트리거

CHECK 는 같은 행 밖을 조회할 수 없으므로 내용 검증은 `BEFORE INSERT OR UPDATE` 트리거로 쓴다(Algorithm 1). 모드 `m` 은 설정 표의 값이며 5절은 이 값만 바꾼다.

```
Algorithm 1. fn_field_value_enforce_evidence (BEFORE INSERT OR UPDATE ON field_value)
 1: m ← current mode; status, derivation ← NULL
 2: if m = P then return
 3: if extractor ∈ {MANUAL, JSON} ∨ grade = NOT_FOUND then return
 4: if m = E1 then return coords present ? GROUNDED : quarantine(NO_COORDS)
 5: if span = ∅ ∧ bbox ≠ ∅ then span ← tokens whose centre ∈ bbox
 6: if span = ∅ then span ← reattach(value, θ); if none then quarantine(NO_EVIDENCE_SPAN)
 7: T ← document_token[span]; if |T| ≠ |span| then quarantine(SPAN_NOT_FOUND)
 8: v ← norm(value); s ← norm(T)
 9: if v = s then (EXACT, GROUNDED)
10: else if type ∉ {number, date} ∧ v ⊂ s then (SUBSTRING, GROUNDED)
11: else if m = E3 ∧ (format(v,T) ∨ glossary(v,s) ∨ sim(v,s) ≥ θ) then (FORMAT | GLOSSARY | SIMILARITY, DERIVED)
12: else quarantine(CONTENT_MISMATCH)
```

판정 컬럼은 호출자가 넣어도 1행에서 덮어쓰고(간극 B), 스팬이 가리키는 토큰이 없으면 7행에서 막힌다(간극 A). 좌표 없는 LLM 값은 6행에서 trigram 유사도 ≥ θ 인 토큰 창을 스팬으로 되찾은 뒤 같은 검사를 거치며, θ 는 결과를 보기 전에 검수 표본으로 고정한다(5절).

### 4.3 격리와 면제 봉인

실패 시 거부하지 않고 격리한다(12행). 행을 UNGROUNDED 로 표시하고 REVIEW_REQUIRED 로 강등하되 검토 큐에 남도록 대표값 자격은 유지하며, 룰 엔진·리포트·재학습 등 기계 경로는 UNGROUNDED 를 제외한 뷰 `field_value_trusted` 만 읽는다. 면제 조항은 자동 경로가 고를 수 없도록 MANUAL 에 실제 행위자 식별자를 CHECK 로 요구한다. 프로토타입은 PostgreSQL·PL/pgSQL 로 구현했으며 운영 배포 상태는 아니다.

## 6. 결론 및 한계

본 논문은 근거 강제를 E0~E3 로 정식화하고, 내용 수준 강제를 DB 트리거와 OCR 토큰 계층으로 구현해 선하증권 데이터에서 절제 실험으로 측정하였다. [5절 결과 요약 — 신뢰구간 하한 기준.] 보장하는 것은 **제안 트리거를 거친 자동 추출값 중** **OCR 토큰 계층에** 선언된 규칙으로 유도되지 않는 값이 자동 확정되지 않는다는 것이며, 모든 환각의 탐지가 아니다. 한계: (1) E3 는 값이 문서 어딘가에 실재함만 보장한다 — 필드–영역 정합 검증이 후속 과제다. (2) 오라클이 OCR 품질에 의존해 OCR 이 놓친 글자는 격리된다(FQR 하한). (3) 격리값의 대체 후보 자동 승격은 없다. (4) 단일 서류 유형·데이터 출처·LLM·노드의 프로토타입 평가다.
