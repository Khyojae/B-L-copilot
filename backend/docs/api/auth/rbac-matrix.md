# RBAC 권한 매트릭스

> 출처: 717 멘토님 피드백 회의 발표 자료

요청 처리 흐름: **요청 → 인증(JWT) → 역할 인가(RBAC 매트릭스) → 소유권 검증 → 실행**

범례: ✅ 허용 · ✗ 불가 · 🔒 본인 소유 건만

| 기능 \ 역할 | 화주 (shipper) | 선사 (carrier) | 포워더 (forwarder) | 은행 (bank) | 관세청 (customs) | 관리자 (admin) |
|---|---|---|---|---|---|---|
| e-B/L 발행 | ✗ | ✅ | ✗ | ✗ | ✗ | 🔓 |
| e-B/L 열람 | 🔒 | 🔒 | 🔒 | 🔒 | 🔒 | 🔓 |
| 소유권 이전 | ✅ | ✗ | ✅ | ✅ | ✗ | 🔓 |
| 서류 업로드 | ✅ | ✗ | ✅ | ✗ | ✗ | 🔓 |
| AI 검증 요청 | ✅ | ✗ | ✅ | ✅ | ✗ | 🔓 |
| L/C 검증 | ✗ | ✗ | ✗ | ✅ | ✗ | 🔓 |
| 통관 조회 | ✅ | ✅ | ✅ | ✗ | ✅ | 🔓 |
| D/O 발행 | ✗ | ✅ | ✗ | ✗ | ✗ | 🔓 |

범례 추가: 🔓 admin은 매트릭스 자체를 우회하는 전체 권한 (고객 대면 역할이 아니라 계정 잠금 해제, 인증서 강제 폐기, 감사로그 조회 등 운영 목적이므로). **단, admin의 모든 쓰기 작업은 예외 없이 `audit_logs`에 기록한다** — 우회하는 건 권한 체크뿐, 감사 추적은 우회하지 않음.

## 역할별 핵심 업무

- **L/C 검증 — 은행만**: 제출 서류가 신용장(L/C) 조건과 일치하는지 심사 → 대금 지급 여부 결정
- **D/O 발행 — 선사만**: 화물 인도지시서 발행 → 정당한 소유자에게 화물 인도 승인
- **admin**: 계정 활성화/정지, 인증서 강제 폐기, 감사로그 조회 등 운영 전용 — 위 비즈니스 매트릭스의 소유권 제약을 받지 않음

## 미들웨어 설계 방향

1. JWT 검증 미들웨어 (`jwtVerify.middleware.js`) → `req.user = { sub, role, org_id, tv }` 설정, `tv`(token_version)가 DB의 현재 값과 다르면 401
2. RBAC 미들웨어 (`rbac.middleware.js`) → `requireRole(...roles)`. `role === 'admin'`이면 매트릭스 체크를 우회하되 `audit_logs`에 기록 후 통과
3. 소유권 검증 (`ownership.middleware.js`) → `🔒` 표시된 기능(e-B/L 열람 등)은 매트릭스 통과 후 리소스의 소유자/관련 당사자인지 추가 확인. admin은 이 단계도 우회

역할-권한 매핑은 이 문서를 그대로 베끼지 않고 `api/src/auth/permissions.js`에 하나의 소스로 코드화해서 문서와 코드가 따로 놀지 않게 한다.
